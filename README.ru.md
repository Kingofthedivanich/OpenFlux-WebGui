# OpenFlux

[English](README.md) | **Русский**

Исследовательский инструмент сетевого стека: TCP-туннель поверх подключаемых
скрытых транспортов вместо прямого соединения с VPN/прокси-сервером.

## Описание

Форк [p1neappleXpress/OpenFlux](https://github.com/p1neappleXpress/OpenFlux),
в паре с [Android-клиентом](https://github.com/Kingofthedivanich/OpenFluxAndroid).
Поверх апстрима этот форк добавляет: обязательное по умолчанию Noise-шифрование,
мультиклиентскую веб-панель управления (`--role=exit-panel`) с опциональным
Telegram-ботом, подключение клиента одним сканом QR, автогенерацию документов
Yandex, multi-stream (несколько документов — один туннель), SSRF-деннилист на
выходной ноде и большой список исправлений корректности/надёжности в
транспортах и на выходной ноде — детали в истории коммитов.

## Как это работает

- Клиент и выходная нода общаются через скрытый транспорт (Yandex.Docs,
  Yandex Volga, MAX/OneMe, Cups.online, Mail.ru Docs) вместо прямого
  соединения.
- Трафик склеивается, сжимается zstd и по умолчанию шифруется Noise NKpsk0
  (X25519 + AES-256-GCM, ротация сессионных ключей).
- Выходная нода пересылает реальный трафик одним из двух бэкендов:
  `--mode=l3` (raw SNAT/DNAT, Linux + root, быстрее всего) или `--mode=l4`
  (gVisor-прокси в userspace, любая ОС, без root).
- `--role=exit-panel` запускает много клиентов в одном процессе за небольшой
  веб-панелью (добавление/удаление, статус, QR-коды, опциональный
  Telegram-бот) — вместо одного процесса выходной ноды на клиента.

## Гайд по установке

```bash
go build -o openflux ./cmd/openflux
```

Выходная нода (выбери один вариант):

```bash
# l3 — Linux, root, быстрее всего
sudo ./openflux --role=exit --mode=l3 --transport=yandex --url="ССЫЛКА_НА_ДОКУМЕНТ"

# l4 — любая ОС, без root
./openflux --role=exit --mode=l4 --transport=yandex --url="ССЫЛКА_НА_ДОКУМЕНТ"
```

Клиент:

```bash
./openflux --role=client --transport=yandex --url="ССЫЛКА_НА_ДОКУМЕНТ"
```

На macOS по умолчанию используется интерфейс utun; на остальных платформах —
SOCKS5-прокси на `127.0.0.1:1080` (`--socks5=<адрес>`, чтобы изменить).

Мультиклиентская выходная нода с веб-панелью вместо процесса на каждого
клиента:

```bash
./openflux --role=exit-panel \
    --panel-addr=127.0.0.1:8088 --panel-user=admin --panel-pass=CHANGE_ME
```

Управляй клиентами (добавление/удаление, QR-коды, Telegram-бот, автогенерация
документов Yandex) из веб-интерфейса. Держи `--panel-addr` на loopback и
заходи через SSH-туннель (`ssh -L 8088:127.0.0.1:8088 user@host`). Прямо на
VPS — [`deploy/menu.sh`](deploy/menu.sh) (`openflux-ctl`), консоль в стиле
3x-ui для обновлений, клиентов и бота, без ручного редактирования
systemd-юнита.

Шифрование обязательно по умолчанию (Noise NKpsk0): нода печатает свой
публичный ключ при первом запуске — передай его клиентам через `--peer-key`.
`--allow-plaintext` отключает шифрование.

Готовые клиенты: [Android](https://github.com/Kingofthedivanich/OpenFluxAndroid/releases)
(клиент этого форка). [iOS](https://github.com/Kingofthedivanich/OpenFluxiOS) —
тоже клиент этого форка (пока только исходники, собирать самому);
[TestFlight апстрима](https://testflight.apple.com/join/BwnAcdus) тоже
работает, но не в паре с шифрованием этого форка — нужен
`--allow-plaintext`. macOS/Linux/Windows: собирай из исходников выше.

Полный список флагов: `./openflux --help`.
