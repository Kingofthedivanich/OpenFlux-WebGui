# Панель выходной ноды

[English](exit-panel.md) | **Русский**

## Описание

`--role=exit-panel` запускает на одном сервере много клиентов за небольшой
веб-панелью с логином. Через неё можно добавлять, менять и удалять клиентов,
смотреть их статус и логи, а также получать ссылку `openflux://` с QR-кодом,
которую сканируют приложения OpenFlux. Панель может сама создать документ
Yandex Volga, если ей дать OAuth-токен Яндекс Диска. На VPS панелью удобно
управлять через консоль `openflux-ctl` ([`deploy/menu.sh`](../deploy/menu.sh)).

## Как это работает

- У каждого клиента свой канал: каталог `<panel-data>/clients/<id>/` с
  `node.conf` в формате `node-install.sh`, сгенерированным ключом AES-256-GCM
  и cookies. Канал обслуживает отдельный процесс `openflux --config … --share`,
  то есть обычная выходная нода ядра, поэтому к ней подключаются стандартные
  приложения OpenFlux.
- У клиента может быть несколько транспортов (Volga, Yandex Docs, Mail.ru,
  Telemost, Boards, Avito, Cups.online) и резервный прямой TCP-порт. Клиент
  держит их одной сессией и переключается между ними по приоритету, если
  какой-то сервис заблокируют.
- Ключ и контекст шифрования при правке клиента не меняются. Комнаты, которые
  экзит создал для Cups.online и Avito, панель записывает обратно в конфиг.
  Поэтому выданная ссылка переживает и рестарты, и правки.
- Упавший процесс канала перезапускается с нарастающей паузой. Статус берётся
  из IPC ядра: на связи ли клиент, трафик, активный транспорт, ожидающая
  капча. Если панель умирает, на Linux вместе с ней останавливаются и каналы.
- Экзит не пускает клиентов на свой loopback, в приватные сети и к cloud
  metadata (169.254.169.254). Флаг `--allow-private` снимает это ограничение.

## Гайд по установке

```bash
go build -o openflux .
./openflux --role=exit-panel --panel-user=admin --panel-pass=CHANGE_ME
```

Панель слушает `127.0.0.1:8088`, открывай её через SSH-туннель:
`ssh -L 8088:127.0.0.1:8088 root@host`. Ссылки содержат ключи клиентов,
поэтому не выставляй панель наружу.

| Флаг | По умолчанию | |
|---|---|---|
| `--panel-addr` | `127.0.0.1:8088` | адрес панели |
| `--panel-user`, `--panel-pass` | — | логин и пароль, обязательны |
| `--panel-data` | `openflux-panel` | клиенты, ключи, каналы |
| `--share-host` | первый публичный IPv4 | адрес в ссылке для прямого порта |
| `--yandex-token-file` | — | файл с OAuth-токеном Диска (`disk.write`), чтобы создавать документы Volga |
| `--allow-private` | выкл. | пускать клиентов в приватные сети хоста |
| `--debug` | `0` | уровень логов каналов |

На VPS: сделай systemd-сервис `openflux-exit` с `WorkingDirectory` в каталоге
бинарника, затем выполни

```bash
sudo ln -sf "$(pwd)/deploy/menu.sh" /usr/local/bin/openflux-ctl
sudo openflux-ctl
```

Консоль сама пропишет ExecStart, умеет обновляться (`deploy/update.sh`
сверяет `SHA256SUMS.txt` и откатывается при неудаче), добавлять и удалять
клиентов, показывать ссылку и QR-код (нужен `qrencode`) и логи.
